# S-Bahn cab-view simulation

**Start with [HOWTO.md](HOWTO.md)**: setup on a new machine (`setup.py`), the 50-combination batch
(`render_batch.py`), every rendering option, camera artifacts, output format and moving the project
(`export_project.py`). The rest of this file documents the internals.

Procedural Blender scene of a German double-track S-Bahn loop for cab-view
synthetic data. Everything is generated by `bpy` scripts from one seed; no
manual modelling, no required downloads.

```
train_simulation/
  build_scene.py          entry point: builds the loop and saves out/sbahn_loop.blend
  render_preview.py       renders validation frames from the cab camera
  examples/consumer_example.py   how the weather / obstacle / renderer modules use the scene
  sbahn_sim/              the package (see module docstrings)
  assets/                 optional CC0 textures / tree models (see "Assets")
  out/                    sbahn_loop.blend, track_lut.json, scene_manifest.json, previews
```

## Requirements

* Blender 4.2 LTS or newer (tested headless with the `bpy` 5.0.1 wheel on
  Python 3.11; the code checks for renamed enums so 4.2 to 5.x should work).
* numpy (ships with Blender).
* No GPU needed. Cycles CPU renders a 960x540 cab frame in roughly 20 to 40 s
  with 48 samples on 4 cores; Eevee works too but needs a GL context.

## Build

```bash
# inside Blender
blender -b -P build_scene.py -- --out out --seed 7 --template stadium --length 8000

# or with the pip wheel (pip install bpy)
python build_scene.py --out out --preview
```

Build time is about 15 s. Flags:

| flag | meaning |
|---|---|
| `--seed N` | changes plan jitter, terrain, land use, scatter |
| `--template stadium/bean/twist` | stadium: two ~1.1 km straights (default, best for 300 to 500 m obstacle milestones); bean: one S-curve; twist: two S-curves (needs >= 8.3 km) |
| `--length M` | target loop length in metres (6000 to 10000) |
| `--no-scatter`, `--no-terrain` | faster builds while iterating |
| `--engine CYCLES/EEVEE` | render engine stored in the file |
| `--set a.b=value` | override any field of `sbahn_sim/config.py`, e.g. `--set scatter.forest_tree_density=0.01` |
| `--preview` | render the validation frames after building |

Outputs in `out/`:

* `sbahn_loop.blend` — the scene. Collections: `Track`, `Catenary`, `Signals`,
  `Hektometer`, `Crossings`, `Terrain`, `NoiseBarriers`, `Station`, `Train`,
  `Lighting`, plus hidden `SRC_*` collections holding instance sources.
* `track_lut.json` — the arc-length lookup table (also stored inside the .blend
  as the text datablock `sbahn_track_lut.json`).
* `scene_manifest.json` — everything the other modules need without opening
  Blender: loop length, straights and curves (s ranges and radii), sector
  layout, mast positions, signal list (name, s, track, lateral, aspect),
  crossings, station, noise-barrier runs, camera and train parameters.
* `config_used.json` — the full config; pass it back with `--config`.

## Coordinate conventions (used by every module and by the manifest)

* `s` = arc length in metres along the **centreline between the two tracks**,
  increasing in the running direction. `0 <= s < length_m`, wrap with
  `tp.wrap(s)`.
* `lateral` = metres to the **right** of the direction of travel. The train's
  track (right-hand running) is at `+2.0`, the opposing track at `-2.0`.
  Masts stand at `+-5.3`, Ks signals at `+-4.55`, noise barriers at `+-6.2`.
* `height` = metres above rail top (Schienenoberkante), along the canted
  "up" vector. Formation is at -0.70, contact wire at +5.30, driver's eye at
  +2.45.
* Curvature > 0 is a left-hand curve; cant (roll) raises the outer rail.

## Track API

```python
from sbahn_sim.track_path import TrackPath
from sbahn_sim.train_rig import place_train
from sbahn_sim import signals

tp = TrackPath.from_scene()          # or TrackPath.load_json("out/track_lut.json") outside Blender
tp.length_m                          # 8047.0
f = tp.sample(s)                     # dict: pos, tangent, right, up, heading, curvature, cant, gradient (vectorised)
tp.point(s, lateral, height)         # world position(s), numpy (N,3)
tp.matrix(s, lateral, height, yaw=0, upright=False)   # 4x4 Matrix, local X right / Y forward / Z up
tp.distance_ahead(s_train, s_obj)    # along-track distance, wraps around the loop
tp.nearest_s(x, y)                   # arc length of the closest centreline point
place_train(s_front, tp=tp)          # moves the 4 cars and "CabCamera" (scene camera)
signals.set_aspect(bpy.data.objects["KsSignal_T0_03"], "Hp0")   # Ks1 / Ks2 / Hp0 / off
```

`upright=True` gives a frame with world-Z up (for placing vertical objects
such as people, cars, signs); the default frame follows cant and gradient
(for anything that sits on the rails).

Ground-truth distance for an obstacle placed at `s_obj` is
`tp.distance_ahead(s_train, s_obj)`; the straight-line distance is the norm
of `tp.point(s_obj, lat) - tp.point(s_train, lat)`. On the stadium template
the two long straights (`manifest["straights"]`) are where 300 to 500 m
sight lines exist; in R = 750 m curves the track leaves the windscreen after
roughly 200 m.

The `Sun` object, the world (`SBahnWorld`) and the `Lighting` collection are
placeholders that `sbahn_sim.conditions` replaces (day/night, fog, rain, headlights). Cab glass is
deliberately left open so a windscreen / droplet shader can be added there.
The three headlights are the `lamp_white` faces on `Car_0`.

## What is generated

* **Alignment** (`track_path.py`): a rounded polygon template becomes
  straights, clothoid transitions (>= 80 m) and circular arcs (R >= 750 m at
  120 km/h); the loop closes by a least-norm adjustment of the straights.
  Cant is 0.75 x equilibrium cant, capped at 160 mm. The profile follows the
  smoothed terrain with gradients capped at 12.5 permille.
* **Permanent way** (`track_geometry.py`): 60E1 rail profile swept along both
  tracks (separate shiny rail-head material), B70 sleepers every 0.60 m as
  Geometry Nodes instances, ballast bed with 1:1.5 shoulders.
* **Catenary** (`catenary.py`): Re 200 style. Mast pairs every 65 m (50 m in
  curves), H-profile masts on concrete foundations, cantilevers with
  insulators, contact wire at 5.30 m with +-0.40 m stagger (outside of the
  curve in curves), messenger wire with sag, droppers every 9 m.
* **Signals** (`signals.py`): Ks main signals every 1200 m per track on the
  right of each track, lamps switchable per signal, Hektometertafeln every
  200 m on the masts, two level crossings on the longest straights with road,
  deck, Andreaskreuze, half barriers (`barrier_angle_deg` property on the
  boom) and warning lights.
* **Terrain** (`terrain.py`): Perlin fBm relief (28 m amplitude); the
  corridor gets a formation, 2 m benches and 1:1.5 embankments / cuttings
  computed from the exact lateral distance; a fine ribbon mesh +-60 m around
  the track and an 8 m grid beyond. Land use is a sector layout along s
  (suburban / forest / field, see `TerrainConfig.sectors`) blended with noise
  and stored as point attributes (`lu_forest`, `lu_field`, `lu_suburban`,
  `tree_density`, `grass_density`, `house_density`, `track_s`, `track_d`).
* **Scatter** (`scatter.py`): Geometry Nodes Poisson scatter of trees,
  bushes, houses and grass tufts driven by those attributes; about 380 000
  instances on the default seed. Trees keep 9 m clear of the centreline.
* **Scenery** (`scenery.py`): noise barriers along 60 % of every suburban
  sector (gaps at the station and crossings), one S-Bahn station with 210 m,
  96 cm platforms, shelters and signs, house proxies.
* **Train** (`train_rig.py`): 4-car Class 423 proxy (16.85 m cars, 3.02 m wide,
  red band, cab open at the windscreen), cab camera 24 mm at 2.45 m, with
  A-pillars, roof lip, desk and a parked wiper parented to the camera.

## Assets

The build is fully procedural. To use CC0 textures instead of the procedural
materials, drop a texture set into `assets/textures/<role>/` (roles are the
keys of `materials._SPECS`: `ballast`, `sleeper`, `grass`, `forest_floor`,
`field`, `soil`, `asphalt`, `concrete`, `noise_wall`, `house_wall`,
`roof_tile`, `platform`, `bark`, ...). ambientCG (`*_Color`, `*_Roughness`,
`*_NormalGL`) and Poly Haven (`*_diff_*`, `*_rough_*`, `*_nor_gl_*`) naming
is recognised; the material then uses box-projected image textures in object
space (no UV unwrap needed).

`python -m sbahn_sim.assets --asset-dir assets` downloads the manifest in
`sbahn_sim/assets.py` from Poly Haven / ambientCG (needs outbound HTTPS to
those hosts; this was not reachable from the build container, so the
download path is untested there). Tree models (`.glb`, `.obj`, `.fbx`,
`.blend`) placed in `assets/models/trees/` replace the procedural proxies.

## Known limitations / next steps

* The train model is a low-poly proxy (trees, houses and cars: see "Detailed scenery models"); swap in real assets via
  the hooks above for photorealism.
* No tensioning equipment (Nachspannung) or signal bridges on the catenary.
* Terrain is a simple relief; no rivers, roads beyond the crossings, or
  bridges. The road at a crossing descends at up to ~6 % from rail level.
* Eevee needs a GPU / GL context; the container validation used Cycles CPU.

## Weather, lighting and day/night (`sbahn_sim/conditions/`)

One call sets the complete environment and returns the effective values to log:

```python
from sbahn_sim.conditions import apply_conditions, PRESETS, resolve
place_train(s)                                    # place first: glare presets use the train heading
eff = apply_conditions(bpy.context.scene, {"preset": "night_rain", "seed": 3, "time_s": 12.5})
# eff -> {"sun_elevation_deg": -9.4, "cloud_cover": 1.0, "visibility_m": 2763.5,
#         "fog_density_per_m": 0.0, "rain_rate_mm_h": 8.0, "headlight_mode": "high",
#         "wiper_angle_deg": 131.2, "exposure_ev": 4.0, ...}   (JSON-serialisable)
```

It can be called again with new conditions at any time; it rebuilds the world, fog and
rain setup and reuses its objects (in `Lighting`, or parented to `CabCamera` / `Car_0`, so
`place_train` carries them). The full key list is in the `sbahn_sim/conditions/__init__.py`
docstring; the main ones:

| key | meaning |
|---|---|
| `preset` | `clear_noon clear_morning partly_cloudy overcast low_sun_glare sunset twilight night_clear night_overcast fog_light fog_dense night_fog rain_light rain_heavy night_rain` |
| `time_of_day`, `date`, `latitude`, `longitude` | real solar position (NOAA), default Munich, 21 June |
| `sun_elevation_deg`, `sun_azimuth_deg`, `sun_azimuth_rel_deg` | direct override; `rel` = relative to the train heading (0 = sun straight ahead) |
| `cloud_cover` | 0..1; procedural cloud deck in the sky, sun dimmed and softened, 1 = overcast |
| `fog_visibility_m` / `fog_density`, `fog_top_m`, `fog_patchiness` | ground fog: extinction 3.912 / V (Koschmieder), layer settles on the track and in lower terrain, banks fixed in the world |
| `haze_visibility_m` | background haze (25 km clear, 8 km overcast / rain) |
| `rain_rate_mm_h` | streak particles, rain extinction 0.25 R^0.63 /km, windscreen drops, wet surfaces |
| `wiper`, `wiper_period_s`, `time_s` | wiper sweep; the swept sector is clean and refills with time |
| `headlights`, `headlight_mode` | Dreilicht-Spitzensignal, `dipped` / `high` (auto: high at night without fog) |
| `exposure_ev` | `auto` = partial auto exposure (night stays dark), or a fixed EV |
| `seed` | clouds, fog banks, drop layout |

What it builds:

* **Sky / sun** (`sky.py`, `solar.py`): Blender 5 `MULTIPLE_SCATTERING` sky (sun disc visible
  to camera rays only, so low-sun glare shows), night sky with suburban light-pollution glow,
  noise cloud deck thresholded by cover, CIE overcast gradient. The Sun lamp's energy follows
  air mass (Kasten-Young + Meinel), its colour per-channel optical depth.
* **Fog** (`fog.py`): one camera-following 9 km volume box. Homogeneous for haze only,
  heterogeneous (height layer x world-fixed noise banks) for ground fog. Single scattering
  with HG g = 0.75 gives the headlight beams; shadow rays skip the fog and a small emission
  term stands in for multiple scattering, so daytime fog is bright grey instead of dark.
* **Rain** (`rain.py`): Geometry Nodes streak field 1.6 to 30 m ahead, each streak aligned to
  the drop velocity relative to the train (speed, fall, crosswind) with length = speed x shutter,
  re-seeded per frame. Windscreen pane with Voronoi drops and airflow streaks refracting through
  water glass; wiper arm; all materials get a wetness insert (darker, glossier) driven by the
  scene property `sbahn_wetness`.
* **Headlights** (`headlights.py`): three spots on `Car_0` at the modelled lamp positions,
  flattened cones, lamp faces glow.

`update_frame(scene, time_s)` in `sbahn_sim.conditions.rain` advances the wiper; a
`frame_change_pre` handler does it automatically when the renderer changes frames.

Validation: `python render_conditions.py --blend out/sbahn_loop.blend` renders every preset to
`out/conditions/` with `conditions_log.jsonl` and `contact_sheet.png`. At 480x270 / 32 samples
each frame takes 22 to 33 s on 4 CPU cores; 960x540 / 48 samples heavy rain took 138 s.

Known limits: no ground splashes or spray kick-up, no motion blur, clouds are a 2D deck (no
volumetric clouds), rain streak brightness is tuned by eye, Eevee settings are set but only
Cycles was validated here.

## Obstacles and YOLO snapshot dataset

`render_dataset.py` places obstacle test cases at exact arc lengths, steps the
train towards them, applies weather/lighting through
`sbahn_sim.conditions.apply_conditions` and writes a YOLO dataset
with per-frame metadata.

```bash
# the 8 test cases x 5 milestone distances (50/100/200/300/500 m), two conditions
python render_dataset.py --mode milestones --conditions clear_noon fog_dense --res 1920 1080 --samples 64
# full approach sequences: one snapshot every 0.5 s at 100 km/h from 520 m to 25 m (+ exact milestones)
python render_dataset.py --mode approach --dt 0.5 --speed 100 --conditions clear_noon night_clear rain_heavy
# a 5 minute loop drive with every obstacle present
python render_dataset.py --mode drive --drive-seconds 300 --conditions overcast
# check the plan and boxes in seconds, without rendering
python render_dataset.py --mode approach --labels-only --out out/dataset_plan
python render_dataset.py --list          # test cases and condition presets
```

Runs resume (finished frames are skipped) and split across processes with
`--shard i n`. `--overlay` writes `overlays/<id>.png` with the boxes drawn
(green = YOLO label, cyan = parked background car, grey = amodal box, red = obstacle in frame but hidden or under --min-px).

**Test cases** (`sbahn_sim/obstacles.py: default_cases`, positions from
`scene_manifest.json`): stalled car on each level crossing, person standing
between the rails, person walking across the track, track worker in hi-vis
on the opposing track, fallen tree across both tracks, branch pile in an
R 750 curve, roe deer on the running track. In `approach`/`milestones` mode
only one case is visible at a time; `drive` shows all.

**Classes** (`dataset.yaml`): 0 person, 1 car, 2 fallen_tree, 3 branches, 4 animal.
With the detailed model library (`sbahn_sim/models`) the car and the fallen
tree use its hatchback and wind-thrown spruce; the person, branch pile and
deer are procedural proxies. Parked cars that the detailed scenery bakes into
house plots are labelled too (class car, `background: true` in the metadata,
cyan in overlays), so a detector is not penalised for finding them; turn
that off with `--no-background-vehicles`. A YOLO row needs at least
`--min-px` visible pixels (default 4); the metadata keeps every object.

**Output** in `--out` (default `out/dataset`): `images/<id>.png`,
`labels/<id>.txt` (YOLO `class cx cy w h`), `meta/<id>.json`, and
`frames.jsonl` / `frames.csv` (one row per frame and obstacle). The frame id
is `<condition>__<case>__<index or mNNNN milestone>`.

Per-frame metadata: timestamp (s since the start of the approach), train
arc length, curvature and gradient, camera matrix and pinhole intrinsics,
the requested and effective conditions (sun elevation/azimuth, fog
extinction and visibility, rain rate, wetness, headlights, exposure ...),
and for every obstacle: class, along-track distance from the train front
and from the camera, straight-line distance and depth, `bbox_amodal`,
`bbox_visible`, visible pixel count, `visible_fraction` (occlusion),
`truncation`, `on_running_track`.

**How boxes are computed** (`sbahn_sim/labels.py`): the amodal box is the
projection of every obstacle vertex; the visible box and fraction come from
casting a grid of camera rays (up to 4 x 4 per pixel for small objects,
48 x 48 per box for large ones) against the obstacle and against the rest of
the scene (terrain, track, catenary, scatter instances, cab frame, other
obstacles). Fog, rain and windscreen objects do not occlude (anything in the
`Lighting` or `Weather` collections or flagged `sbahn_non_occluding`), so a
box is labelled whenever the object is geometrically in line of sight; use
`visible_px`, the distances and the logged fog visibility to decide what a
detector could be expected to see. At 1920 x 1080 with the 24 mm cab lens
(fx = 1280 px) a 1.8 m person is ~46 px tall at 50 m, ~12 px at 200 m and
~5 px at 500 m.

Render cost (Cycles CPU, 4 cores, 960 x 540, 24 samples): ~50 s per frame
on the proxy scenery, ~80 s on the detailed scenery (`out/hd/`), plus
5 to 60 s of labelling per frame on the detailed scenery when many parked
cars are near the view. Scale with pixels and samples. Eevee runs but uses software GL in a
headless container (~4 min/frame), so it only pays off with a GPU.

## Label validation (`validate_dataset.py`)

Independent check of the YOLO boxes against what Cycles renders: it renders a small set of frames with the
normal pipeline, re-renders each as a 1-sample Object Index / Material Index pass (weather glass, rain and fog
hidden), and compares every label's visible box with the bounding box of the rendered mask pixels.

    python validate_dataset.py --blend out/sbahn_loop.blend --out out/validation/proxy
    python validate_dataset.py --blend out/hd/sbahn_loop.blend --out out/validation/hd --frames-preset hd
    python validate_dataset.py --blend out/hd/sbahn_loop.blend --out <dir with meta/> --skip-beauty   # masks only

Needs `pip install OpenEXR`. Results of the 2026-10-01 run: `out/validation/REPORT.md`.

## Detailed scenery models (`sbahn_sim/models/`)

The low-poly proxies are replaced by a procedural model library (on by default,
`--set scatter.hd_models=false` brings the proxies back). Everything is real,
opaque geometry generated in-script, so nothing needs downloading.

* **Trees** (`trees.py`): a recursive branch grower with presets for Fichte (spruce), Kiefer
  (pine), Buche (beech), Eiche (oak), Birke (birch), Ahorn (maple), plus shrubs and saplings.
  Bark tubes with species bark shaders (birch lenticels, pine's orange upper bark), individual
  leaves or spruce shoot sprays, 50k to 150k faces per tree near the track and 15k to 35k for the
  far LOD (`SRC_TreesFar`, used on the terrain grid). Foliage colour varies per instance and per
  leaf, and inner leaves are darker.
* **Ground vegetation** (`vegetation.py`): meadow grass tufts, tall grass with seed heads,
  yarrow / buttercup / knapweed / chicory clumps, bracken.
* **Buildings** (`houses.py`): Einfamilienhaus (1 or 2 storeys, dormer, solar panels, chimney),
  Doppelhaus, Mehrfamilienhaus (3 to 4 storeys, balconies, gable / hip / flat roof), barn, commercial
  hall, garage. Windows with frames, sills and half-closed roller shutters; plaster and roof-tile
  colours vary per instance. Each house in `SRC_Houses` is a plot with a driveway or car park and
  parked vehicles (object property `sbahn_background_vehicles` = how many).
* **Vehicles** (`vehicles.py`): Kleinwagen, Golf-class hatchback, Kombi, saloon, SUV,
  Transporter, Sprinter, 7.5 t box truck, with wheels and rims, lamps, EU plates and mirrors.
  `vehicles.obstacle_parts(kind, rng, paint)` and `library.fallen_tree_parts(rng, species)`
  return the `(parts, mats)` format of `obstacles.BUILDERS`, so the obstacle builders can use
  these models directly.

With the library the default build is ~165 MB and takes ~40 s; a 960x540 / 48-sample Cycles cab
frame takes 60 to 75 s on 4 cores (forest sections up to ~100 s) instead of 40 to 47 s with
proxies. Trees now keep 12 m from the centreline (`terrain.tree_clearance_m`, was 9) so crowns
stay out of the clearance gauge, and grass is denser (`scatter.grass_density` 1.8).

Own models: put `.glb .gltf .obj .fbx .blend` files into `assets/models/trees/` or
`assets/models/houses/` and they replace that category (trees feed both LODs). Models should
be in metres, Z up, origin at the base.
